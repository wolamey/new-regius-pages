## 3. P0: безопасность

В текущем публичном bundle обнаружены два абсолютных Bitrix24 REST webhook URL. Значения, user ID и token не выводились и не сохранялись в артефактах.

Обнаруженные методы после удаления секретной части URL:

- `crm.item.add`;
- `lists.element.get.json`.

Также в bundle присутствуют два `no-cors` сценария. Это подтверждает, что критическая проблема из аудита 18.08.2026 на дату повторной проверки не устранена.

**Обязательное действие вне локального контура:** отозвать/ротировать раскрытые webhook, удалить их из исходников и истории публикаций, перевести операции на защищённый server-side endpoint с минимальными правами.

## 5. Формы и аналитика основного сайта

- В публичном bundle присутствует `no-cors`, поэтому frontend не может надёжно подтвердить приём лида.
- В текущей форме нет offer code четырёх новых страниц и квалификационного второго шага.
- В bundle найдены Яндекс Метрика и Facebook Pixel; фактическая legal/cookie-конфигурация требует отдельной проверки владельца.
- PII нельзя передавать в события аналитики.

## 7. Реализованный безопасный локальный план

- Один server-side endpoint `POST /api/leads`.
- CSRF-token + HttpOnly SameSite cookie.
- Origin allowlist, rate limit, honeypot, ограничение тела запроса.
- Zod-валидация и нормализация всех полей.
- Idempotency key и блокировка повторной доставки.
- Нейтральные ответы без Bitrix24 body и stack trace.
- Логи содержат только event, request ID, offer code и timestamp.
- Три режима: `disabled`, `mock`, `bitrix`; default — `disabled`.
- Webhook читается только из server environment и не попадает в клиентскую сборку.

## 8. Блокеры и передача

1. Передать репозиторий и ветку основного сайта.
2. Ротировать публичные Bitrix24 webhook до любого production-релиза.
3. Утвердить существующие CRM-поля и права server webhook.
4. Утвердить production host, способ запуска Node endpoint или эквивалент на текущем backend.
5. Утвердить юридические тексты и реальные контакты.
6. После переноса повторить скан source, bundle, network и публичных файлов; исторический аудит не заменяет проверку собранного релиза.
